# Safety, privacy and prototype boundaries

- This is **NOT** a medical device, clinical assistant, diagnosis engine, or production patient-support system.
- Fictional clinician names, FAQ templates, schedules, and funnel data are present solely for investor demonstration.
- FAQ text has not been approved by a qualified treating dentist. Real deployment requires clinical sign-off, update owners and expiration review.
- Safety routing uses basic keyword rules and has significant blind spots. It must not be relied on to recognize all emergencies.
- When the demo recognizes severe pain/swelling or clinical treatment decisions, it routes to professional care or human review. This is an example of a future control, not a tested emergency triage system.
- There is no external API call or local storage, but **the repository is public if published**. Do not add real patient conversations, clinical records, contact details, secrets, or vendor source code.
- Any real deployment involving Thai health data needs privacy/legal review, appropriately limited access, informed notices and applicable consent or other legal basis, retention controls, and security testing.
- Real-time availability and appointment write-back require an authoritative system and vendor-approved interface. A green simulation result is not a confirmed appointment.
